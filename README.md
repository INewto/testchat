# Чат

Простой онлайн-чат на PHP, Redis и Vue 2. Сообщения приходят без перезагрузки
страницы (короткий опрос раз в секунду). При входе показываются все сообщения
за последние 30 минут, дальше подтягиваются только новые. Вход и выход
фиксируются системными сообщениями «Юзер 1 вошёл в чат» и «Юзер 1 покинул чат»;
выходом считается закрытие вкладки или окна браузера.

## Окружение для проверки

- **PHP 8.1 или новее** с расширениями `json` и `mbstring` и работающими
  сессиями (каталог сессий должен быть доступен на запись).
- **Composer** — ставит единственную зависимость, `predis/predis`. Это чисто
  PHP-клиент Redis, расширение `redis` для PHP не требуется.
- **Redis с поддержкой Lua-скриптов (`EVAL`)**; проект проверялся на Redis 7.0.
  По умолчанию чат подключается к `127.0.0.1:6379`.
- **Веб-сервер с PHP**, у которого корень сайта (docroot) указывает на `public/`.
  Для локальной проверки достаточно встроенного сервера PHP, команда ниже.
- **Два браузера** или два изолированных профиля одного браузера: чат
  проверяется с двух сторон одновременно.
- Кодировка файлов и данных — UTF-8.

Если Redis слушает не `127.0.0.1:6379`, перед запуском веб-сервера задать в его
окружении переменные `REDIS_HOST` и `REDIS_PORT` (порт числом).

## Установка

Из корня проекта:

```sh
composer install
```

Команда создаёт `vendor/` и `vendor/autoload.php`. Без неё ни одна страница не
откроется: `src/bootstrap.php` подключает автозагрузчик при старте.
`composer.lock` лежит в репозитории, поэтому ставятся зафиксированные версии.

## Запуск

1. Запустить Redis. Команда зависит от способа установки (например,
   `redis-server` или запуск службы); важно, чтобы он отвечал на адресе из
   настроек выше.
2. Из корня проекта запустить веб-сервер с docroot `public/`. Например,
   встроенный сервер PHP:

   ```sh
   php -S 127.0.0.1:8080 -t public
   ```

3. Открыть `http://127.0.0.1:8080/` в двух браузерах.

Каталог `logs/` создаётся сам при первой ошибке, вручную его создавать не надо.
Он лежит вне `public/`, поэтому недоступен из браузера.

## Сценарий проверки

1. В первом браузере ввести имя `Юзер 1` и нажать «Войти», во втором — `Юзер 2`.
2. В чате появятся «Юзер 1 вошёл в чат» и «Юзер 2 вошёл в чат». Справа
   в списке «В чате» будут оба имени.
3. Отправить из первого браузера `Привет! 😁`, из второго — `Hello! 😁`. Оба
   сообщения появятся в обеих вкладках без перезагрузки, с временем, именем
   автора и emoji без искажений.
4. Закрыть вкладку первого браузера. Через несколько секунд во втором
   браузере появится «Юзер 1 покинул чат», а в списке справа останется
   только `Юзер 2`.
5. Снова открыть чат в первом браузере: должна появиться форма «Вход в чат».
   Чат до ввода имени открываться не должен. После ввода имени появится
   «Юзер 1 вошёл в чат».
6. Обновить страницу (F5) в любом браузере: чат остаётся открытым, лишние
   «вошёл в чат» и «покинул чат» не появляются.
7. Обновить страницу позже: в истории будут все сообщения за последние
   30 минут, более старые не показываются; новые продолжают приходить без
   перезагрузки.

## Кратко об устройстве

- `public/index.php` — страница и серверный шаблон; отдаёт имя, CSRF-токен и
  настройки в `window.CHAT_CONFIG`.
- `public/js/chat.js` — обычный JavaScript: опрос `/api.php?action=fetch`,
  курсор `since`, отправка, форматирование времени и передача данных в Vue.
- `public/js/vue.min.js` — локальная копия Vue 2.7.16, без обращения к CDN.
- `public/api.php` — четыре действия: `fetch`, `join`, `send`, `leave`.
- `src/chat.php` — состояние чата в Redis; записи и чтение ответа собраны в
  атомарные Lua-скрипты.
- `src/bootstrap.php` — настройки, сессия, CSRF, заголовки, клиент Redis.
- `src/log.php` — ошибки в `logs/chat-ГГГГ-ММ-ДД.log`, без значений аргументов
  в стеке вызовов (там могли бы оказаться имена и тексты сообщений).

Имя и внутренний идентификатор при отправке берутся из сессии, а не из запроса.
CSRF-токен проверяется на каждом POST, сообщения выводятся текстовой
интерполяцией Vue (`v-html` не используется), есть ограничение частоты отправки.
